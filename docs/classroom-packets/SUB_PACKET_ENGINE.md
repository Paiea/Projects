# Substitute Packet Engine

Reusable public template for making a substitute day understandable to students and easy for a substitute to run. Keep all examples generic and free of student records.

## Principle

The substitute should not need to imitate the regular teacher's entire instructional system.

A good sub day is:

- safe
- calm
- predictable
- visibly instructional
- paper-first when technology is unreliable
- easy to recover when the class gets loose

The packet is an anchor, not a race.

## Required artifact set

A strong sub bundle usually contains:

1. **Student packet**
2. **Sub guide** matched to the final packet
3. **One-page packet map** with exact page numbers
4. **Quick answer sheet** for objective items
5. **A few optional challenge packets**
6. **Slides**, only if they make modes/timing clearer and have a paper fallback

Do not let these artifacts drift apart during iteration.

## Build order

Use this order:

1. Decide what is actually being taught/practiced today.
2. Build the student packet.
3. Freeze the final page order.
4. Build the packet map from that frozen order.
5. Build the sub schedule using the same page map.
6. Build/update the answer key from the same final questions.
7. Update slides to the same sequence.
8. Render and verify everything.

If the student packet changes afterward, rematch all dependent artifacts.

## Student-facing front page

The packet front should answer two questions immediately:

### What am I learning today?

Use 4–6 short kid-readable goals.

### How do I use this packet?

Recommended language:

> We will work on most pages throughout the day. You MAY go ahead when you finish early. If you are truly stuck, mark a small `?` and keep moving. When the class reaches that page, come back and fill it in. Goal: finish MOST of the packet by the end of the day. Careful work beats racing.

## Substitute-facing page map

Create a compact table:

| Page | Student task | Planned block |
|---|---|---|
| 1 | learning map + warm-up | morning |
| 2 | math practice | math / technology backup |
| 3 | true coloring page | quiet reset |
| 4 | spelling | word work |
| 5 | grammar | ELA |
| 6 | writing | writing |
| 7 | true coloring page | quiet reset |
| 8 | read + think | after read-aloud |
| 9 | math thinking | math |
| 10 | create | afternoon |
| 11 | checkpoint / mixed review | independent check |
| 12 | drawing/design | create / finish |

This is a **reference architecture**, not a required exact sequence. Change it to match the actual day.

## Running academic pages

The substitute does not need to lecture through every item.

For each new page:

1. state the goal
2. read the direction
3. model/discuss one example when useful
4. release a short chunk
5. circulate and check 1–2 items
6. stop/review/carry unfinished work if needed

Accept appropriate Grade 2 representations: drawings, equations, bar models, words, tools, and brief oral explanation when the task allows them.

## Mode switches

Use a small library instead of the same reset repeatedly.

### Energy down
- Silent Detective
- Slow Motion
- Sound Hunt
- Mirror Mode
- true coloring page

### Neutral switch
- Spot the Change
- Secret Number
- Mystery Drawing

### Energy up
- Jump Battle
- Would You Rather
- short movement challenge

Choose the reset based on where students need to **land** next.

A high-energy activity is not automatically a problem. The instructional skill is switching back to serious/learning mode afterward.

## Simple behavior recovery

Use a short correction ladder:

1. proximity / nonverbal cue
2. short direction
3. choice inside the expectation
4. brief reset with current work
5. normal school support for unsafe, aggressive, eloping, or persistent disruption

If the whole room gets loose:

1. stop
2. re-establish attention
3. seats / one clear task
4. reduce response freedom temporarily
5. use a short quiet or seated reset
6. restart learning

Avoid long lectures.

## Early finishers

Order:

1. check/fix current work
2. return to skipped `?` items if the class has already taught those pages
3. optional challenge work
4. silent reading / established early-finisher routine

Challenge packets are not required pages.

## End-of-day finish block

Build this into the sub schedule explicitly.

Suggested script:

> Go back to any small `?` marks or unfinished class pages. We are trying to finish MOST of the packet today. If your required work is in good shape, choose challenge work or silent reading.

This makes working ahead useful without turning the packet into a race.

## Final sub-day QA

Before printing, verify:

- packet page count
- exact page titles
- page map matches packet
- sub schedule matches page map
- answer key matches current questions
- slides match sequence
- math answers are solved
- matching/sorting tables have enough physical spaces
- no ambiguous directions
- no accidental repeated exact tasks from recent packets
- page breaks make sense
- true coloring pages are actually coloring pages, not disguised drawing assignments
- technology has a paper fallback
- final finish block exists

Then render every PDF and inspect every page.
