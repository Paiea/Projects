# Praxis 5003 V2.2 Design

## Goal

Make the Mathematics subtest useful as both a hard adaptive trainer and a substantially more Praxis-like mock, while preserving the existing app and the other three subtests.

## Sources and authority

- Official content scope: the uploaded ETS Praxis 5003 study plan.
- Difficulty/style calibration: the uploaded PrepSaret mathematics notes and examples, especially multi-step real-world application, representation switching, reasonableness, measurement, data interpretation, and algebraic relationships.
- Existing app behavior: current `praxis/` source on the `praxis-v2-1-publish` branch.

The app must generate original questions. It must not copy PrepSaret or ETS item wording.

## Problems to fix

1. Generated distractors can collide with the correct answer, producing two visually identical choices with only one internally marked correct.
2. Many 5003 items are one-step procedural drills and can be completed far faster than a realistic subtest.
3. Full/mock sessions can repeat shallow families such as direct metric conversions several times.
4. Validation checks structure but not semantic answer integrity or session-level variety.

## Product split

### Trainer

Practice mode may intentionally repeat a topic or reasoning family. It should be useful for attacking a weakness quickly and may contain easier scaffolding items.

### Mock

A full 5003 subtest should remain 50 questions with the existing 40/30/30 domain weighting, but the item mix should skew much harder:

- about 10-15% direct/one-step
- about 50-55% two-step application or representation
- about 30-35% multi-step, interpretation, or cross-skill reasoning

The exact percentages are composition targets, not claims about ETS item difficulty.

## Reasoning-family model

Replace shallow operation families with reusable reasoning families. Initial V2.2 families should include:

- convert -> divide -> interpret remainder
- rational-number multistep context
- percent/ratio comparison with an intermediate quantity
- estimate -> compute/check reasonableness
- model a context with an expression/equation -> evaluate/solve
- linear relationship across equation/table/context
- perimeter/area/volume with changed dimensions
- coordinate geometry with a computed quantity
- elapsed-time or measurement conversion embedded in a second step
- measures of center with an outlier or changed datum
- interpret/select a graph based on what a display would show
- compound probability or counting-based probability at elementary-test scope

Each family owns its answer construction and distractor logic.

## Integrity gate

Every generated MCQ must pass a quality validator before entering a session:

- at least two choices
- valid `correctIndex`
- no duplicate normalized choice text
- no duplicate numeric-equivalent choices when values can be parsed safely
- designated correct choice is unique after normalization
- non-empty stem/explanation/topic/domain/skill/family

If a generated item fails, discard it and generate another. Never score a known-invalid item.

## Session quality gate

For a full 5003 mock:

- preserve 20/15/15 domain counts
- cap exact reasoning-family repetition so one family cannot dominate
- avoid repeated fingerprints
- prefer medium/hard items, with only a small easy share
- validate the final session before returning it

Topic practice may relax the family cap because repetition is intentional.

## UI and scoring

Keep the current four-choice UI for V2.2. Numeric-entry and multi-select are desirable later, but they are not required to make this pass materially harder and safer.

Results remain explicitly a practice metric, not an ETS scaled-score prediction.

## Testing

Add automated tests that prove:

- the known rounding duplicate-answer bug is rejected
- thousands of generated 5003 items contain no duplicate/equivalent choices
- full 50-question sessions preserve 20/15/15 weighting
- full sessions meet family-repeat caps and minimum difficulty mix
- existing smoke/validation/replay tests still pass

## Scope boundary

Do not redesign 5002, 5004, or 5005 in this pass. Use the 5003 engine as the pattern to transplant later after it proves useful in real study.
