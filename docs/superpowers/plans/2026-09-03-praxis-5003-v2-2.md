# Praxis 5003 V2.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make 5003 materially harder and safer by adding semantic item validation, harder reasoning families, and mock-session composition rules.

**Architecture:** Keep the existing static browser app. Add a focused 5003 quality layer inside `content-expansion.js`: item validators, harder family generators, and mock composition rules. Keep `app.js` mostly unchanged except for defensive session validation messaging if needed. Extend Node-based validation scripts so generated-item and full-session quality are testable outside the browser.

**Tech Stack:** Static HTML/CSS/JavaScript, Node.js validation scripts, browser localStorage.

**Spec:** `docs/superpowers/specs/2026-09-03-praxis-5003-v2-2-design.md`

## Global Constraints

- Preserve the existing 5003 domain weighting: 40% Numbers and Operations, 30% Algebraic Thinking, 30% Geometry/Measurement/Data/Statistics/Probability.
- Generate original questions; do not copy ETS or PrepSaret item wording.
- Keep 5002, 5004, and 5005 behavior stable in this pass.
- Keep results labeled as practice accuracy, not an ETS scaled-score prediction.
- Keep the app static and local-first with no new runtime dependencies.
